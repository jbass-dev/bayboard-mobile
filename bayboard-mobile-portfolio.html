Under the hood

One workflow, two clients.

BayBoard Mobile is designed to use the same Firebase project and Firestore documents as the existing web board, so counter staff and technicians can work from their own screens.

  • Firebase Authentication, including guest access
  • Firestore snapshot listeners for live updates
  • Atomic ticket completion + parts inventory updates
  • Elapsed-time severity and accessible status cues

Project highlights

Built for more than a pretty screen.

The mobile client brings service workflow, shared data, and practical accessibility into a native Android experience.

↻

Reactive live board

Firestore snapshot listeners flow through Coroutines and Flow into ViewModel state, keeping the UI in sync as tickets change.

⇄

Consistent data

Completing a ticket and decrementing the parts used are designed to commit in one Firestore transaction.

◉

Accessible urgency

Elapsed-time severity uses color, shape markers, and spoken labels rather than relying on color alone.

▦

Native Android UI

Kotlin, Jetpack Compose Material 3, Navigation Compose, and MVVM with reactive state.

✓

Testable logic

Business rules and Firestore mapping are separated from the UI to support JVM unit tests.

⚙

Real-world domain

Designed around the quick-lube workflow: waiting queue, service bays, technician assignment, parts, and restocking.
